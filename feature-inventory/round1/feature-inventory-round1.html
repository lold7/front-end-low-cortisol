สิ่งที่เจอระหว่างไล่ทดสอบ

  • Checkout ใช้ที่อยู่ของคนอื่น [D1]
    ถ้าลูกค้าไม่ได้ติ๊กเลือกที่อยู่ JS ส่ง address_id=1 ไปแทน ทดสอบแล้วออเดอร์ #1006 ของ Somchai ถูกผูกกับที่อยู่ของ John
  • รีเซ็ตรหัสผ่านโดยไม่ยืนยันตัวตน [A3]
    กรอกแค่อีเมลกับรหัสใหม่ก็เปลี่ยนรหัสได้ทันที
  • ใครก็สมัคร admin ได้ [A5]
    /backoffice/register เปิดให้ทุกคนโดยไม่ต้องล็อกอิน
  • หน้ารายละเอียดออเดอร์ใช้ไม่ได้ [E2]
    /account/orders/:id แสดง “No orders yet” ทุกครั้ง
  • /faq และ /condition เป็น 404 [B9]
    มีลิงก์ใน footer และมีไฟล์ view แต่ไม่มี route
  • ไม่มีการจัดการสต็อกฝั่งลูกค้า [B6, D3, F4]
    ไม่แสดงสต็อก และไม่ตัดสต็อกหลังสั่งซื้อ (Harry Potter ยัง 72 หลังสั่งไป 3 เล่ม) สินค้าหมดถูกซ่อนแค่จากรายการ/ค้นหา
  • หน้าหมวดหมู่เขียนตายตัว [B3]
    /categories และเมนู navbar ไม่ได้อ่านจาก DB
  • ค้นหาด้วยชื่อผู้แต่งไม่ได้ [B5]
    ค้นได้แค่ชื่อหนังสือกับคำอธิบาย และไม่มีตัวกรองราคา/เรียงลำดับ
  • สถานะ Processing ไม่มีจริง [F8]
    มีแท็บใน admin แต่ enum ใน DB มีแค่ pending/completed/cancelled
  • บัญชีตัวอย่างใน init.sql ล็อกอินไม่ได้ [—]
    hash รหัสผ่านของ admin@bookstore.com และ John เป็นค่าหลอก (อีเมล John ยังพิมพ์ผิดเป็น john@bookstore.comcart_items) ต้องสมัครบัญชีใหม่เพื่อทดสอบ
  • รูปปกไม่ตรงกับหนังสือ [B6]
    เช่น The Great Gatsby แสดงปก Leonardo da Vinci, Harry Potter แสดงปก “The Elements” (ไฟล์รูปใน products/ ไม่ตรงกับข้อมูล)

C1 เพิ่มสินค้าลงตะกร้า
ทำงานปกติ
 ปุ่ม Add to Cart ใน /product/:id (POST /cart/add) ลูกค้า
  • ต้องล็อกอินก่อน (guest → redirect login)
  • สินค้าเดิม + format เดิมซ้ำ → บวกจำนวนเพิ่ม (คนละ format แยกเป็นคนละรายการ)

  • ตรวจสต็อกฝั่ง server: จำนวน 1–10, สินค้าหมด → แจ้ง error, ของในตะกร้า (ทุก format) + ที่จะเพิ่ม เกินสต็อก → แจ้ง error
